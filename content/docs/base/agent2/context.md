# 会话上下文

1. 滑动窗口: 取最近 N 轮消息
2. 语义检索: 召回最相关的 topK 轮候选消息
3. 保留关键消息: 例如我想了解一下 iPhone17..., 先判断某条消息是否为关键消息, 如果是则标记为关键消息, 整个会话都携带

## 早期消息, 截断 or 压缩?

### 中英文的 token 估算

- 中文 1 个汉字 1 个 token
- 英文 4 个字母 1 个 token

层 1 (最近的几轮消息) 可以占 70%; 层 2 (中间层的消息) 可以占 30%; 层 1 超过 70% 降级一批到层 2, 层 2 超过 30% 压缩成摘要

S = 摘要覆盖到的最后一条消息 ID
L = 层 1 的第一条消息 ID

1. 最近的几轮消息原样保留 (ID >= L)
2. 中间层的消息 (S < ID < L)
   - 用户消息原样保留
   - Agent 消息保留一定长度的前缀
   - 小的工具调用结果可以保留, 大的工具调用结果可以替换为占位符
3. 最远的、未被压缩的几轮消息「异步」压缩成摘要; 并标记为「历史摘要」; 后续上下文压缩不会二次压缩已被压缩的历史摘要 (ID <= S)

上下文窗口大小 (不是消息的轮数) 超过预算时, 后台异步开启摘要任务, 任务完成后将摘要存储到数据库; 等到下一轮, 将消息历史中最远的、未被压缩的几轮消息替换为摘要, 上下文压缩不会阻塞用户

历史摘要不需要全量携带, 一条摘要对应多轮对话, 携带 2-3 条历史摘要即可

```js
const messages = [
  // 角色、业务范围、行为约束
  // prompt cache 按前缀匹配, system 字段保持不变以命中前缀缓存
  { role: "system", content: "你是电商 Agent..." },
  // 中间层的消息
  // 用户消息原样保留
  // Agent 消息保留一定长度的前缀
  { role: "user", content: "..." },
  { role: "assistant", content: "..." },
  // 最近的几轮消息: 原样保留
  { role: "user", content: "..." },
  { role: "assistant", content: "..." },
  // 用户当前的消息
  { role: "user", content: "..." },
  // 本轮会话的材料: 包括历史摘要
  { role: "user", content: "[历史摘要] ..." },
];
```

上下文窗口 = 系统提示词 + 工具定义 + (AGENTS.md 指令文件 + skills 技能 + MCP 等动态加载的工具 + subagent 定义 `agents/<subagent>.md`) + **历史消息**

如果用户单轮输入不超过 X (user_message / tool_result), 模型单轮输出不超过 Y (max_output_tokens), 则 N 轮的 token 消耗是: N * (X + Y)

## langgraph state

langgraph 的 state 是节点间共享的数据结构, 每个节点都可以读写 state, state 有一个 message 字段, 即历史消息
