并发GC中的对象消失问题（Tombstone Problem）

三色标记法在并发场景下可能错误回收可达对象
黑色（已扫描完毕，不再重扫）
灰色（正在扫描中）
白色（未扫描，视为不可达）
虚线框 = 已被回收 / 不存在
Step 1：shade(A, gray) 回收器操作
Step 2：shade(C, black) 回收器操作
Step 3：C.ref3 = C.ref2.ref1 赋值器操作（并发）

C 新增直接引用 B
Step 4：A.ref1 = nil 赋值器操作（并发）

B 仅通过 C.ref3 可达
Step 5：scan(A) → shade(A.ref1, gray) 回收器操作

GC 以为 B 已不可达（实际上 C.ref3 还指向 B）
Step 6：shade(A, black) → B 被错误回收！ 回收器操作

C 是黑色 → GC 不检查 C.ref3 → B 永远无法被标记

💀 B 实际可达（C.ref3 → B），但被错误回收！
问题根因总结

关键矛盾：C 已经是黑色（GC承诺不再重扫），但赋值器在并发中给 C 新增了到 B 的引用（C.ref3 = B）。

同时 A 断开了对 B 的引用（A.ref1 = nil），导致 GC 扫描 A 时找不到 B。

GC 的逻辑是："B 只被灰色对象 A 引用，A 扫完就没了，所以 B 不可达"。 但 GC 忽略了：B 还被黑色对象 C 引用着，而 C 因为已是黑色，GC 不会回头检查。

解决方案：写屏障（Write Barrier）—— 当灰色/黑色对象向白色对象写入引用时，自动将该白色对象重新标为灰色，确保不会被漏掉。
